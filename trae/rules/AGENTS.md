# 项目开发铁律

## 1. 技术栈（需提前确认）
- 开工前必须明确技术选型，一旦确定，后续开发不得擅自更换。
- 推荐选型（仅作参考）：FastAPI / React+Go+MySQL 等，根据项目实际调整。

## 2. 目录结构与职责（开工前先输出）
- 每次新项目开工前，必须先输出完整的项目目录结构，并说明每个目录的职责。
- 目录需遵循分层架构（如 handler / service / repository / model / config 等），严禁跨层调用。
- 目录结构确认后方可开始编码。

## 3. 代码设计原则（最高优先级）
- **高内聚低耦合，单一职责**。
- **严禁过度设计**：不要为了“绝对完美”写出难以理解的复杂抽象代码。
- **严禁兜底与猜测**：不知道接口字段或业务逻辑时，必须停下来提问，不许瞎编；不许写冗余的备选方案和兜底逻辑。
- **性能底线**：不考虑极端小众情况，避免后端计算冗长，避免前端响应变慢。
- **简洁可读**：代码优先保证可读性和简洁性。

## 4. 工作流（每项任务强制遵循）
1. 先出计划（涉及哪些文件/方法/大致逻辑），等我确认。
2. 确认后执行，生成代码。
3. 完成后自我 Review，检查是否符合分层和设计原则。
4. 有不确定的地方立刻提问，不要猜测。

## 5. 窗口协作规范（多 Agent 场景）
- 每个新窗口必须先读取本规则。
- 规划窗口只做决策，不写代码；执行窗口按任务单编码，完成后贴 Review 结果。
